Why SAVER

Agents can pay autonomously.
They still need to know what to trust.

SAVER adds an independent verification layer between information and execution. It does not replace wallet policy, transaction simulation, or deterministic security controls. It answers a different question: is the factual premise supported by current evidence?

02

03

Integrate

One request.
Built for software, not forms.

Send a claim to POST /v2/verify. An unpaid request returns HTTP 402 with payment requirements in the PAYMENT-REQUIRED header. An authorized x402 v2 wallet client signs and retries the same JSON body. Use POST /v2/verify for linked evidence; POST /verify keeps the original format.

When to call SAVER

Check the factual premise in your workflow.

Use it to check a claim from another tool, challenge an unsupported statement in a report, or obtain cited findings for a research decision. Use local code for arithmetic, and dedicated security tools for wallets, token contracts and transaction simulation.

Confidence is model-assessed, not a calibrated probability. Source links let you inspect provenance; they do not guarantee the interpretation is correct. An insufficient_evidence result is a completed paid verification.

Security by design

Verification is evidence.
Not permission.

SAVER is designed to complement — not bypass — wallet policy, approvals, transaction simulation, sanctions checks, or deterministic controls.
